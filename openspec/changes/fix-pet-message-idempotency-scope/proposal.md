# fix-pet-message-idempotency-scope

## Why

`client_msg_id` is generated by the client and is intended to make retries idempotent for the current user. The existing schema made it globally unique, and replay lookup used only `client_msg_id + role`. A malicious or unlucky cross-user collision could route into replay logic outside the current user's conversation boundary.

## What Changes

- Scope the server-side `client_msg_id` uniqueness constraint to `(user_id, client_msg_id)`.
- Scope idempotent replay lookup to the current user and current conversation.
- Add regression coverage proving two users can reuse the same client message id without leaking or replaying each other's messages.

## Impact

- Database: additive migration altering the `pet_messages` unique key; historical migrations remain unchanged.
- API behavior: retry idempotency remains unchanged for the same user; cross-user collisions are isolated.
- Tests: handler-level regression plus existing conversation idempotency coverage.
